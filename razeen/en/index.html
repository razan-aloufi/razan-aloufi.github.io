About the founder

CASE OWNER

Razan Aloufi

Founder, Razeen Academy · Cloud Computing Specialist

Specialty
Cloud Computing Specialist

I work across every area of cloud computing, every day: building infrastructure, securing it, and aligning it with Saudi Arabia's Cloud Cybersecurity Controls (NCA CCC) and the Personal Data Protection Law (PDPL).

Most hands-on cloud content is written in English, and many learners study the theory without ever touching a real environment — or connecting it to the regulations that actually apply in Saudi Arabia.

I built Razeen to close that gap: labs you solve yourself, in a language you think in, with every vulnerability tied to the control it breaks.

My goal is for every Razeen learner to graduate having actually done it — not just memorized it.

Simulated Labs

بيئات المحاكاة
Available

Run inside the Razeen browser on scenarios, files and settings in their real formats.

How it works
  1. Starts the lab in the browser
  2. Reads and edits synthetic files (IAM policy, CloudTrail log, Terraform)
  3. Submits the fix
  4. The server verifies the answer
  5. Progress and achievements are saved
Properties
  • No cloud resources per learner
  • Server-side verification
  • Near-zero running cost

In Razeen todayLAB-02 · LAB-03 · the five challenges

SHARED REAL

Shared Real Labs

بيئات حقيقية مشتركة
Available

One real resource at the cloud provider, used by every learner within set permissions.

How it works
  1. Installs the provider's tool (e.g. AWS CLI) locally
  2. Connects to the real resource in the academy account
  3. Runs real commands
  4. Enters findings in Razeen
  5. The server verifies and saves the result
Properties
  • Read-only: the resource policy allows no edits or deletes
  • Synthetic data, never real data
  • Budget alert on the academy account

In Razeen todayLAB-01: a shared, read-only Amazon S3 bucket

ISOLATED REAL

Isolated Real Labs

بيئات حقيقية معزولة
In Development

A separate cloud environment per learner, created at start and deleted at the end.

How it works
  1. Starts the lab; the system checks plan and sessions
  2. The lab engine creates resources at the provider
  3. Gets temporary access to their environment
  4. Runs real commands and experiments
  5. Result saved, then resources deleted
Properties
  • Full isolation between learners
  • Fixed session length and auto-shutdown
  • Write access inside their own environment only

In Razeen todayBuilt now: plan and session-quota checks. The engine itself is in development

Technical components

  • Lab EngineIn Development

    Receives the environment request and orchestrates every other component, from start to deletion.

  • Cloud ConnectorIn Development

    Connects to the academy's AWS, Azure and Google Cloud accounts with limited permissions.

  • Environment ManagerIn Development

    Creates lab resources from a ready template and tracks their state.

  • Session ManagerIn Development

    Counts monthly sessions per plan and tracks session time.

  • Access ControlIn Development

    Checks account and plan, and grants temporary access to the environment only.

  • Lab ValidatorAvailable

    Verifies the learner's solution on the server and saves progress and achievements.

  • Cleanup ManagerIn Development

    Deletes every temporary resource after finishing or when time runs out.

Lab Validator runs today in every lab and challenge. Plan and session-quota checks are built within Access Control and Session Manager; the other components are in development.

Auto-shutdown In Development

  1. Time runs outThe session length ends (set by admins, 60 minutes by default)
  2. Session dropsIf the learner disconnects, the environment is kept briefly per the operating policy
  3. DeletionCleanup Manager deletes resources and closes the session
  4. SavedThe learner's progress and achievements are always kept
